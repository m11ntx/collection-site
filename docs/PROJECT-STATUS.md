**Read this first when resuming in a new session.** Captures where the front-end
is, what exists, how to run it, and what comes next — so no context is lost.

_Last updated: CS-18 — Launch Preparation. Version 1.0.0, ready for launch (pending owner actions)._

## What this project is

The **M11NTX storefront** — a fast, dependency-free site (vanilla HTML5 / CSS3 /
ES6, no frameworks, no build step) deployed on **GitHub Pages**. Premium soccer
(jersey) culture, dark/gold identity.

- This repo: `collection-site` → https://github.com/m11ntx/collection-site
- Data pipeline (separate): `../catalog-pipeline` →
  https://github.com/m11ntx/catalog-pipeline (generates `data/*.json` + images).
- The two communicate through **one contract only: the JSON in `data/`**.

Architecture:
```
data/*.json → api.js → catalog.js → ui.js → screen
```

## Pages & navigation

```
Landing (index.html)
  → Collection detail  (pages/collection.html?slug=…)
    → Club             (pages/club.html?slug=…)
      → Jersey         (pages/jersey.html?slug=…)
```

- **index.html** — fixed nav (revealed on scroll), mobile menu, search overlay
  (layout only), the **frozen hero/landing**, and the **Collections** grid
  (rendered from JSON).
- **pages/collection.html** — banner + clubs of a collection (reads `?slug=`).
- **pages/club.html** — club crest/league + jersey grid (reads `?slug=`).
- **pages/jersey.html** — premium gallery (swap/fade/zoom, no libs), specs
  (brand/type/category/season/version/gender), reference size grid, and the
  **customer journey** (CS-11): How It Works timeline, Import Information, FAQ.
  CTA is **Consultar Disponibilidade** → official Instagram (intermediation
  model; no direct sales, no stock badge).
- **Institutional pages (CS-16)** — `pages/{about,how-it-works,faq,contact,privacy,
  terms,intermediation-policy}.html`, generated by `scripts/gen/gen_pages.js` on the
  approved design system. Header nav + a full institutional footer link to them.
- Subpages reuse the nav/footer via `<base href="../">`.

## JavaScript layers (`assets/js/`)

| File | Role |
|------|------|
| `api.js` | `fetch()` data layer (tolerates empty/missing files) |
| `image-loader.js` | asset pipeline: `getImage()`, lazy load, fade-in, branded fallback |
| `catalog.js` | renders collections grid, collection detail, club page, jersey page |
| `filters.js` | JSON-driven filter engine + reusable UI (CS-10). See `docs/filters.md` |
| `search.js` | accent-insensitive smart search (CS-12); shares the filter engine. See `docs/search.md` |
| `seo.js` | dynamic SEO (CS-13): meta/canonical/OG/Twitter + JSON-LD (Org/WebSite/Breadcrumb). See `docs/seo.md` |
| `analytics.js` | decoupled telemetry (CS-14): `trackEvent` → GA4 + Clarity, config-driven. See `docs/analytics.md` |
| `config/site.js` | single source of truth: URLs + analytics ids/toggles (loaded first) |

**Production loads the minified bundles** (`*.min.js` / `*.min.css`). Edit the
sources above, then run `node scripts/gen/minify.js` to regenerate (CS-15).
| `ui.js` | nav reveal, mobile menu, search overlay, scroll-reveal, jersey gallery |
| `main.js` | bootstrap — routes by page (which container id is present) |

## How to run

Uses `fetch()`, so serve over HTTP (not `file://`):

```bash
python -m http.server 8000     # then open http://localhost:8000
```

GitHub Pages serves it over HTTP automatically.

## Key decisions (do not re-derive)

- **The hero / landing is FROZEN** — approved design; do not restyle it.
  Also treat as approved: navbar, footer, Collections grid, design system, palette.
- **JSON is the single source of truth** — never hardcode catalog data.
- Subpages use `<base href="../">` so all paths resolve from the site root.
- **Intermediation model (CS-11)** — M11NTX does not sell directly. The Jersey
  page shows no stock badge/checkout; the CTA is **Consultar Disponibilidade**
  and opens the official Instagram (`INSTAGRAM_URL` in `catalog.js` — confirm the
  handle). Availability is confirmed during service; the size grid is
  reference-only. `sizes[].stock` and the CS-10 availability filter still use the
  data (RN-006/RN-007) — only the product page presentation changed.
- `buyUrl` in `products.json` is now **legacy/unused** on the page (kept in the
  data; the CTA routes to Instagram instead).
- **Institutional (CS-16)** — the 7 institutional pages are generated by
  `scripts/gen/gen_pages.js` (edit content there, re-run, then `minify.js`). The
  full footer + `email` (config/site.js → `hello.m11ntx@gmail.com`) are new. The
  **frozen landing keeps its minimal
  footer** by design; the institutional footer is on content pages only.
- **Performance (CS-15)** — HTML loads `*.min.js`/`*.min.css`. Sources are the
  editable truth; **re-run `node scripts/gen/minify.js` after editing any CSS/JS**
  or production will serve stale code. No visual change was made. `filters`/`search`
  min bundles exist but aren't loaded yet (future catalog page). See `docs/performance.md`.
- **Config (CS-14)** — `config/site.js` (`window.CONFIG`) is the single source for
  the Instagram URL and analytics ids/toggles; it loads first on every page.
  `catalog.js` and `seo.js` read the Instagram URL from it (safe fallback). To turn
  on analytics, set the GA4/Clarity `id` + `enabled: true` there — nothing else.
- **SEO (CS-13)** — production base is `https://m11ntx.github.io/collection-site`
  (single source in `assets/js/seo.js` `SITE.url` + `scripts/gen/gen_sitemap.js`;
  also hardcoded in the static `<head>` tags). Re-run `node scripts/gen/gen_sitemap.js`
  after catalog data changes. On a GitHub Pages project site, submit the sitemap
  via Search Console (host-root robots.txt isn't this repo). See `docs/seo.md`.
- Brand assets are generated by `scripts/gen/apply_assets.py` from the originals
  in `assets/images/Novas/`; favicon pack in `assets/icons/`.
